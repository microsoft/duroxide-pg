## Notes

- Generated with `scripts/generate_migration_diff.sh 26` against PostgreSQL 15.19.
- Signature is unchanged, so the migration uses `CREATE OR REPLACE`; the
  function keeps its OID and `EXECUTE` grants.
- Renewal takes the per-instance advisory lock that `fetch_orchestration_item`
  takes, then reads the time again with the clock rule from migration `0025`.
  The expiry check and the new deadline use that time, and the deadline never
  moves earlier.
- Queue rows are updated before the instance lock, the order used by
  `ack_orchestration_item` and `abandon_orchestration_item`.
- `idx_instance_locks_lock_token` serves the token lookups in
  `renew_orchestration_item_lock`, `ack_orchestration_item` and
  `abandon_orchestration_item`, which scanned `instance_locks` before. It is
  unique because a token must name exactly one instance.
