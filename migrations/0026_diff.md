## Notes

- Renewal now acquires the same transaction-scoped per-instance advisory lock
  as `fetch_orchestration_item` before either function takes its conflicting
  row locks.
- The post-lock `UPDATE` repeats the token and expiry predicates because a
  concurrent fetch can make a token stale while renewal waits for the advisory
  lock.
